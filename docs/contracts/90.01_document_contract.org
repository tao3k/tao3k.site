* JDex coordinate policy
JDex is a machine-queryable Org navigation index, not a second metadata
authority. A coordinate record uses an Org TODO keyword as its lifecycle state
and links directly from the heading to the responsible Org file.

#+begin_src org
** ACTIVE [[file:../compare/50.02_community_product_reference_set.org][50.02 Community Product Reference Set]]
#+end_src

The JDex state machine must be declared with =#+TODO=. Plain description rows
such as =- Status :: Active=, coordinate property drawers, duplicated standalone
links, and copied target metadata are prohibited.

The linked target file is the sole metadata authority. Its header owns
=#+TITLE=, =#+DATE=, =#+AUTHOR=, =#+FILETAGS=, =#+STATUS=, =#+OWNER=,
=#+AUDIENCE=, and =#+CLAIM_MATURITY=. Repository validation resolves the
=file:= link and requires the JDex TODO state to match the target =#+STATUS=:
=DRAFT -> draft=, =REVIEW -> review=, =ACTIVE -> active=,
=ACCEPTED -> accepted=, =SUPERSEDED -> superseded=, and
=ARCHIVED -> archived=.

* Repository-level requirements
The repository gate additionally requires:
- no Markdown documentation;
- no non-portable =id:= links in repository documentation;
- every relative =file:= link resolves from its owning document;
- every file under =content/= declares a root =CONTRACT_ORG= property;
- local and Pages configurations register this same contract source;
- no duplicate required keyword;
- a valid claim-maturity value.

The accepted maturity values are =shipped=, =active-development=, =research=,
=vision=, and =policy=. A repository or design record must not be presented as
shipped evidence merely because it exists.

* Deployment use
The local and GitHub Pages theme configurations list this file under
=[contracts].sources=. Orgize WASM validates the contract source before target
documents are evaluated. A malformed contract is a deployment error, not an
empty successful registry.

* Ownership boundary
Orgize owns contract parsing, source validation, evaluation, diagnostics, and
the WASM transport. Org Zhixing owns configuration and deployment admission.
tao3k.site owns this repository-specific policy and its public claims.
